# Operating an app fast with cua-driver

A run's time is almost all model turns: each reply you make costs seconds, a tool call well under one. Make as few replies as you can.

1. Start with the tool call. No opening message, no plan written out, no progress notes between steps. Write one short final message.
2. Do not call `start_session` or `end_session`.
3. Look once: `get_window_state` with `include_screenshot: false`. The element tree (labels, values, `element_index`) is enough for forms, tables, lists and buttons. Take a screenshot only when the tree cannot tell two controls apart.
4. Put every action you already know into the same reply as several tool calls. They run one after another, in the order you give them. The `element_index` values stay valid until your next `get_window_state`, so a whole form (fields, choices, checkbox, submit) is one reply.
5. Look again only when an action makes something appear that you must target next: a dialog, a menu or submenu, a popover, the next step of a wizard, search results. Put that `get_window_state` at the end of the same reply as the action.
6. Enter text with `set_value` or `type_text` on an `element_index`, not with pixel coordinates.
7. Check once at the end with `get_window_state` (`include_screenshot: false`). Never press a submit, save or confirm button a second time unless the check shows it did not take.
