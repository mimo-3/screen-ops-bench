# Operating an app fast with cua-driver

Most of a run's time is spent waiting for you to decide the next step, not in the tools. Fewer turns make the run faster.

1. Do not call `start_session` or `end_session`. They only draw a cursor overlay.
2. Look once. Call `get_window_state` with `include_screenshot: false`. The element tree (`structuredContent.elements`, with labels and values) is enough for web forms, lists and buttons. Take a screenshot only when the tree cannot tell two controls apart or a control has no label.
3. Plan every step from that one snapshot, then act. The `element_index` values stay valid until your next `get_window_state`. Do several actions in a row without looking again in between.
4. Look again only when an action makes something new appear that you must target next: a dialog, a menu or submenu, a popover, the next wizard step, search results. Use `query` to see only the lines you need.
5. Enter text with `set_value` or `type_text` on an `element_index`. Avoid pixel coordinates.
6. Check the result once, at the end, with `get_window_state` (`include_screenshot: false`, a `query` for the fields you changed). Fix only what is wrong.
7. Do not write progress messages between steps. Write one short final message.
